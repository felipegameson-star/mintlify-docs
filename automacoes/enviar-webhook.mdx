## O que é a ação "Enviar Webhook"

A ação **Enviar Webhook** permite que uma automação do Vistum faça uma requisição HTTP para qualquer URL externa — como um workflow no n8n, Make, Zapier ou seu próprio sistema.

## Quando usar

- Quando quiser que o n8n/Make execute algo ao receber uma mensagem específica
- Quando precisar criar registros em sistemas externos (CRM legacy, ERP, planilha)
- Quando quiser notificar um servidor próprio sobre eventos do atendimento

## Configurar a ação

<Steps>
  <Step title="Adicione um nó Ação ao fluxo">
    No editor de automações, clique em **+** e selecione o nó **Ação** (laranja).
  </Step>
  <Step title="Selecione Enviar Webhook">
    No campo **Tipo de ação**, selecione **Enviar webhook**.
  </Step>
  <Step title="Configure a URL">
    Cole a URL de destino (deve ser HTTPS e acessível publicamente).

    Exemplos:
    - n8n: `https://n8n.seudominio.com/webhook/abc123`
    - Make: `https://hook.make.com/xyz...`
    - Seu servidor: `https://api.seusite.com/webhook/vistum`
  </Step>
  <Step title="Configure o body (opcional)">
    Você pode personalizar o payload JSON usando variáveis:

    ```json
    {
      "nome": "{{name}}",
      "telefone": "{{phone}}",
      "etapa": "{{stage}}"
    }
    ```
  </Step>
  <Step title="Salve e teste">
    Salve a automação e dispare manualmente para testar (ou use o nó de teste).
  </Step>
</Steps>

## Variáveis disponíveis no body

| Variável | Valor |
|----------|-------|
| `{{name}}` | Nome do contato |
| `{{phone}}` | Telefone do contato |
| `{{email}}` | E-mail do contato |
| `{{company}}` | Empresa do contato |
| `{{notes}}` | Observações do contato |
| `{{stage}}` | Nome da etapa atual do pipeline |
| `{{assigned_agent}}` | Nome do atendente responsável pelo contato |
| `{{lastMessage}}` | Última mensagem trocada com o contato |

Além dessas, qualquer variável criada durante o fluxo também funciona aqui — por exemplo, uma resposta salva num bloco **Perguntar** (`{{email_lead}}`) ou um dado vindo de um gatilho de compra (`{{webhook.product}}`, `{{webhook.amount}}`). Veja a lista completa em [Usar variáveis nas mensagens](/automacoes/variaveis).

<Warning>
  As variáveis aqui são sempre **planas** — `{{name}}`, `{{phone}}`, `{{stage}}` — e não com notação de ponto. Escrever `{{contact.name}}` ou `{{pipeline.stage}}` **não funciona**: o Vistum não reconhece esse formato e o texto fica exatamente assim, literal, no corpo enviado. Use sempre os nomes da tabela acima.
</Warning>

## Payload automático (sem body customizado)

Se você não preencher o body, o Vistum envia um payload padrão estruturado:

```json
{
  "event": "automation.webhook",
  "automationId": "auto_xxx",
  "workspaceId": "wks_xxx",
  "timestamp": "2025-05-07T14:30:00.000Z",
  "contact": {
    "id": "cnt_xxx",
    "name": "Nome do Contato",
    "phone": "5511999887766"
  },
  "pipeline": {
    "cardId": "card_xxx",
    "fromStageId": "stage_xxx",
    "toStageId": "stage_yyy"
  }
}
```

## Detalhes técnicos

- **Timeout**: 10 segundos
- **Método**: POST
- **Content-Type**: `application/json`
- **User-Agent**: `Vistum-Automations/1.0`
- **Tentativas**: 1 (sem retry automático na ação de automação)
- **Log**: cada execução é registrada no histórico com URL mascarada + HTTP status + tempo de resposta

<Warning>
  A URL de destino deve ser **HTTPS** e acessível pela internet. URLs internas (localhost, IPs privados) são bloqueadas automaticamente por segurança.
</Warning>

## Limite técnico: até 3 chamadas HTTP por execução

<Warning>
  Cada **execução** de uma automação (ou seja, cada vez que um contato passa pelo fluxo) pode fazer no máximo **3 chamadas HTTP no total** — e esse limite é **compartilhado** entre o bloco **Enviar Webhook** e o bloco **HTTP** (chamada genérica a uma API). Não é 3 de cada, é 3 somando os dois.

  Se o seu fluxo tiver, por exemplo, 2 blocos **HTTP** e 2 blocos **Enviar Webhook** no mesmo caminho de execução, a 4ª chamada simplesmente não é feita.
</Warning>

Se o seu caso de uso precisa de mais integrações do que isso, o caminho é concentrar a lógica no seu servidor de automação (n8n, Make, etc.): a Vistum faz **uma única chamada** para lá, e o restante das chamadas HTTP acontece do outro lado, sem esse limite.

## Diferença: ação de automação vs webhook outbound

| | Ação webhook na automação | Webhook outbound (Configurações) |
|--|---|---|
| Disparo | Quando a automação executa | Quando eventos do CRM acontecem |
| Configuração | Dentro do fluxo da automação | Configurações → Webhooks |
| URL customizável | Sim | Sim |
| Body customizável | Sim (com variáveis) | Não (payload padrão) |
| Log | Histórico da automação | Histórico de deliveries do webhook |
| Retry automático | Não | Sim (5x exponencial) |
